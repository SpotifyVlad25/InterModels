# InterModels — выделенный сервис рендеринга композиток

## Зачем

Cloudflare Worker остаётся точкой входа Telegram, управляет D1 и готовыми публикациями. Тяжёлый этап Resvg rasterization переносится в отдельный Node.js-контейнер с независимо выделяемой памятью. Это убирает зависимость растеризации от лимита памяти одного Worker isolate.

Worker по-прежнему:
- получает фотографии из Telegram и уменьшает их без кадрирования;
- собирает SVG карточки и передаёт его вместе со шрифтами сервису;
- проверяет PNG-ответ и публикует его в Telegram.

Рендерер:
- принимает только авторизованные POST-запросы;
- ограничивает размер тела, SVG, шрифтов и готового PNG;
- использует Resvg native Node binding, а не WASM внутри Worker;
- не хранит изображения и не пишет их на диск.

## Развёртывание контейнера

Соберите и запустите каталог `renderer/` на контейнерном хостинге (например, Railway, Render или Fly.io). Для сервиса задайте переменные:

- `COMPOSITE_RENDERER_TOKEN` — длинный случайный секрет не менее 32 байт;
- `PORT` — порт, который предоставляет платформа (обычно 8080);
- `NODE_OPTIONS=--max-old-space-size=768` уже задан в Dockerfile; для production контейнеру рекомендуется выделить не менее 1 GiB RAM.

После запуска проверьте `GET /health`: ответ должен содержать `{"ok":true}`.

## Подключение Worker

Добавьте в Cloudflare Worker secrets/vars:

- `COMPOSITE_RENDERER_URL` — базовый HTTPS URL сервиса, без завершающего `/render`;
- `COMPOSITE_RENDERER_TOKEN` — тот же секрет, что задан контейнеру.

При наличии обеих переменных Worker использует внешний сервис. Если обе переменные отсутствуют, сохраняется локальный WASM-рендерер как режим совместимости. Если настроена только одна переменная, генерация завершается явной ошибкой конфигурации.

Не помещайте токен в репозиторий, wrangler.toml, GitHub Actions workflow или сообщения Telegram.

## Ограничения текущего этапа

Пачки до 20 ФИО уже сохраняются как отдельные задания в D1. Webhook быстро подтверждает приём партии, а Cron worker последовательно обрабатывает до двух заданий за запуск. Прогресс и отмена привязаны к операции; зависшие задания переводятся в ошибку после 10 минут. Это намеренно последовательная обработка, а не 20 параллельных рендеров: так нагрузка на графический движок остаётся контролируемой. Worker всё ещё скачивает и подготавливает фотографии и собирает SVG, поэтому размер входных данных ограничен текущими проверками.

## Проверка перед включением для агентства

1. Развернуть сервис и проверить /health.
2. Установить два Worker secrets.
3. Запустить одну тестовую композитку и сверить геометрию, шрифты и PNG с текущим макетом.
4. Проверить четыре исходных фото без кадрирования и без изменения порядка.
5. Измерить память и длительность на серии минимум из 20 композиток.
6. Только после успешного теста считать внешний путь production-ready.
