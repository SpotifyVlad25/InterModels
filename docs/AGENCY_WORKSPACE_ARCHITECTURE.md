# InterModels — целевая архитектура рабочего кабинета

## Подтверждённые продуктовые правила

- Модель не загружает, не заменяет и не выбирает фотографии.
- Модель не просматривает и не получает свою композитку.
- Директор управляет анкетой, параметрами, фотографиями и главным фото.
- Композитка — внутренний рабочий документ агентства.
- Секретарь — отдельный третий Telegram-бот. Команда `/comp Фамилия` ищет модель по фамилии.
- Если найден один человек, секретарь выдаёт карточку сразу. Если совпадений несколько — показывает inline-кнопки выбора. Если нет совпадений — сообщает об этом.
- Генерация всегда использует текущие данные D1 и выбранные директором фотографии.

## Макет композитки

Зафиксированная композиция по мотивам предоставленного примера Asia's Next Top Model:
1. Большой вертикальный портрет слева сверху.
2. Два меньших вертикальных фото справа, одно под другим.
3. Четвёртое вертикальное фото слева снизу.
4. Справа снизу — имя и фамилия, параметры в компактных колонках и фирменная подпись InterModels.
5. Все четыре изображения кадрируются в вертикальном соотношении 3:4.
6. Контакты агентства размещаются один раз; никаких повторяющихся шапок/подвалов.
7. Макет должен поддерживать мужские и женские анкеты и отсутствие необязательных параметров.

## Предлагаемое разделение компонентов

### 1. Model bot
Только подключение к анкете и сервисные сообщения. Никакого API для загрузки фотографий, изменения параметров или получения композитки.

### 2. Director bot + Mini App
Директорский бот открывает Mini App. Mini App предоставляет:
- список и поиск моделей;
- просмотр и редактирование полей профиля;
- загрузку/замену/удаление четырёх фото-слотов;
- назначение главного фото профиля;
- предпросмотр и ручной запуск генерации;
- историю версий композитки.

Каждый API-запрос Mini App должен проверять Telegram Web App `initData` на сервере и сверять Telegram ID с `DIRECTOR_TELEGRAM_ID`. Нельзя доверять переданному клиентом user ID или username.

### 3. Secretary bot
Отдельный webhook route `/webhook/secretary` и отдельный секрет `SECRETARY_BOT_TOKEN` / `SECRETARY_WEBHOOK_SECRET`.
- `/comp <фамилия>` — поиск только среди активных моделей.
- Один результат — сразу выдать актуальную карточку.
- Несколько результатов — inline keyboard с полными именами; callback привязан к конкретному model ID и проверяется по Telegram ID разрешённых сотрудников.
- Ноль результатов — короткий ответ «Модель не найдена».
- Файл отправлять как изображение для быстрого просмотра и PDF как документ, если обе версии созданы.

Состав разрешённых пользователей секретаря должен быть серверным allowlist. До подтверждения состава использовать только директора и владельца из уже имеющихся переменных.

## Хранение фотографий и файлов

Рекомендуемое хранилище — Cloudflare R2. В D1 сохраняются только метаданные и object keys; бинарные фото и готовые файлы не помещаются в D1. Bucket и binding должны быть созданы/подключены отдельно перед включением загрузки. Ключи объектов генерирует сервер, а не клиент.

## Схема данных

Миграция `0005_agency_workspace.sql` добавляет:
- цвет волос и глаз в `model_profiles`;
- `model_photos`: четыре позиции на модель, MIME, размер, R2 object key и отметку главного фото;
- `composite_cards`: версии изображений/PDF и fingerprint исходных данных;
- `agency_audit_log`: журнал изменений директором.

Миграция пока подготовлена в feature-ветке и не должна применяться к production до проверки и подключения R2.

## Автоматическое обновление карточки

Изменение параметров или фото должно помечать карточку как устаревшую (по source fingerprint). Для MVP проще и безопаснее генерировать карточку при вызове `/comp`, если fingerprint изменился, и сохранять новую версию. Позже можно добавить фоновые задачи/очередь.

## Этапы реализации

1. Проверить и стабилизировать текущий Model/Director webhook flow; исправить двухэтапную регистрацию: ФИО → собственный Telegram contact → запись номера в phone → заявка директору.
2. Подключить R2 и API для директорского управления фото и параметрами.
3. Создать Mini App с серверной проверкой Telegram initData.
4. Реализовать рендерер композитки в PNG и PDF.
5. Добавить Secretary bot, `/comp`, поиск по фамилии и выбор дубликатов.
6. Добавить typecheck и тесты в CI, затем отдельно согласовать production rollout.

## Что ещё требуется от владельца

- Создать третьего Telegram-бота через BotFather и передать токен через GitHub Secret, не в чат.
- Создать R2 bucket (или подтвердить доступный существующий bucket).
- Выбрать окончательный список пользователей, которым разрешено пользоваться Secretary bot.
- После публикации Mini App — настроить домен/кнопку запуска в Telegram, если это не будет автоматизировано через доступные настройки.

## Текущее состояние, проверенное по репозиторию

- Worker `intermodels`, D1 binding `DB`, два webhook route: model и director.
- Текущие переменные Worker включают MODEL/DIRECTOR bot tokens и webhook secrets, OWNER и DIRECTOR Telegram IDs.
- Таблицы: models, registration_requests, model_profiles, bot_sessions, bot_topics.
- В текущем коде регистрация допускает поиск отдельно по ФИО или телефону. Это ещё не согласованный двухшаговый сценарий ФИО → запрос контакта.
- В проекте пока нет R2 binding, Mini App, Secretary webhook, загрузки фото и генератора композиток.
- README в корне содержит устаревшие утверждения о том, что D1 и боты не настроены; его нужно актуализировать при следующем проходе.
